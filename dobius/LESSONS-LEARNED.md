## 2026-08-29 — Two round trips lost to `xargs` on paths that all contain a space
- Tried: a tree-wide rebrand rewrite as `grep -rlwI "Buzz" "<abs path>" | xargs sed -i '' 's/…/…/g'`, then `grep -rlwIZ … | xargs -0 …` after the first failed.
- Failed because: every path under `~/Projects (Code)/` contains a space, so bare `xargs` split each filename in two (`sed: /Users/bayou/Projects: No such file or directory`); and BSD grep has no `-Z`, so the "fix" still printed newline-separated names and `xargs -0` passed all 131 of them as a single argument (`File name too long`). Neither attempt wrote anything — sed exits on the first bad path — but that was luck, not design.
- Works instead: `grep -rlwI --null "<pattern>" "<abs path>" | xargs -0 sed -i '' 's/[[:<:]]X[[:>:]]/Y/g'` — long-form `--null`, `-I` to skip binaries so a matching `.png` is never fed to sed, BSD word boundaries `[[:<:]]`/`[[:>:]]` (no `\b`), and `-i ''` with its mandatory empty suffix. Verify with `git status --porcelain` before re-running a partially-failed rewrite.
- Same turn: a compound probe (`cd … && C=… && echo … && grep …`) was refused by the worktree guard — the shape `learned-worktree-session-commands` already forbids. Inside a worktree session the rule is absolute: one bare command per Bash call, absolute paths, `git -C <abs worktree>` instead of `cd`.
