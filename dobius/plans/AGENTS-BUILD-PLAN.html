Agents, end to end

One front screen, a real task pipeline, and a loop that actually finishes. Sequenced so the expensive work only starts once the cheap work has proven it will pay off.

The call: prove one task before building anything on top of it.

Zero board tasks have completed successfully. One ran, cost $0.76, and produced nothing — not because there was no pipeline, but because “SKINS inside dobius” had no description. Five agents conferring about that same task is four dollars and still no answer.

Every phase below is ordered so that a failure costs pennies instead of an afternoon. The front screen comes last on purpose: it is a window onto data that mostly does not exist yet.

Rules for parallel agents

Packages within a phase touch disjoint files and can run at once. Anything that edits board-dispatch.ts runs alone — P1-1 and P2-1 both do, so they are sequential with respect to each other.

  • Never both edit one file. If two packages need the same file, one waits.
  • Do not touch src/main/daemon/. It runs terminal sessions. Changing it forces a daemon restart, which kills every open terminal.
  • No fake data. If the real value is not available, omit the element.
  • Verify by looking. A screenshot of the running app, not a passing build.
  • Real exit codes. pnpm run build:mac then ec=$? — never chained after an echo.
  • Agents move cards to Review, never Done. Closing is a human decision.
Installing. Install and relaunch the app. Do not restart the daemon — it serves PTYs only, app code reloads with the app, and restarting it destroys live terminal sessions for no benefit.

Ordered so the cheapest thing that can disprove the plan runs first. Phase 0 is one task and an afternoon; it decides whether the rest is worth building.
