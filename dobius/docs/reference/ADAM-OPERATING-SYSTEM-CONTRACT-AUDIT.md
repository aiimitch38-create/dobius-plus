## System boundary

ADAM's operating-harness plan assigns ADAM objectives, authority, jobs, decisions, verification, follow-ups, and distilled knowledge; it assigns Dobius+ projects, worktrees, terminals, agent status, and raw provider transcripts to Dobius+. ADAM source implements part of this split through a SQLite job store and DobiusClient adapter, but its service also has terminal dispatch, worktree/agent launch, monitoring, and event ingest.

The October cloud workstation work introduces another durable job authority in Dobius+ through CloudJobStore and QueuePort. ADAM already has a parent-job-to-Dobius worker path in source: its supervisor records the parent job and ordered steps, runs project/context preflight, launches a worker through DobiusClient/CLI, awaits the agent, and records verifier evidence and reported state. That path is separate from the missing C02 bridge: inspected source does not map ADAM parent jobs to CloudJobStore job/attempt IDs or share C02 leases, reservations, start permits, cancellation, or transactional state. Thus this audit does not claim that all ADAM-to-Dobius execution integration is absent; it identifies the distinct ledger/lease authority gap and has no live authenticated handoff proof. The canonical plan maps C00 to inventory/preservation/contracts; C01 verified cloud protection; C02 catalog and durable queue; C03 independent phone/laptop selection; C04 background storage monitoring; C05 laptop/VPS workers and isolated Hermes; C06 shared Kanban; C07 catalog/archive/hydration; C08 Laya recovery/offline evaluation; C09 advisory integration; C10 approved automatic policies; and C11 recovery drill/both-app delivery. Current manifest source checkpoints (including C00 bound terminal transport and observer, C07 catalog, C11 resume/terminal binding) are narrower implementation slices within that program, not deployment proof. Queue dispatch remains disabled, AWS deferred, and historical Storage queue paused.

## Integration invariants

1. One objective authority and one execution authority per operation. If ADAM owns a parent objective while Dobius owns process/lease identity, their mapping and crash reconciliation must be explicit; do not mirror mutable job state casually.
2. Keep IDs distinct: ADAM job/task, cloud job/attempt, project, repository, worktree, device/host, SSH connection incarnation, terminal/PTY, agent run, and root incarnation.
3. Revalidate identity and policy immediately before claim, terminal write, spawn, cancellation signal, and acceptance. Recheck after async approval/provider work; stale authority means no side effect.
4. Events are observations. Bind authenticated producer/run identity and generation/cursor. Missing, duplicate, or reordered events require reconciliation. Done, idle, and exit-zero are not accepted completion.
5. Share bounded task fields, context digests, artifact pointers, and evidence only. Do not copy raw transcripts or personal memory into queue state by default.
6. An unavailable ADAM endpoint remains unavailable; do not silently substitute a local mock or second authority. Health, endpoint, service revision, identity, state directory and timeout need observable contracts that do not disclose credentials.
7. Laya remains advisory. It cannot grant access, approve writes, or complete a job.

## Open implementation and runtime gates

- Choose the ADAM/cloud job relationship and a single canonical public status projection; define cancellation and offline recovery.
- Add explicit authenticated ADAM-to-Dobius cloud transport/API binding; existing adam-connection and source constructors do not prove it.
- Map ADAM handshake identity to enrolled Dobius project/device/root, preserving native root and SSH connection incarnation.
- Route writes through one server-owned policy capability and exact approval; prove no side effect after denied, expired, or stale authorization.
- Define event producer authentication, cursor/generation/replay/reset, bounded retention and privacy across ADAM, Dobius runtime, apps, and observers.
- Reconcile verifier receipts without promoting reported/done/exit-zero, ADAM's deterministic text-floor result, or caller-supplied iMessage `passed`/`receipt` to independent human acceptance.
- Keep queue unavailable or paused until host registration, worker enrollment, cleanup, budget/capacity and verifier gates pass.
- Current runtime acceptance remains separate: ADAM authenticated health/revision, installed Dobius revision, cloud configured/liveDispatchReady, VPS state, mobile old-host refusal, and physical phone behavior each require current evidence. No end-to-end runtime probe occurred in this audit.
