## Concrete integration gaps for the system-level contract

1. Define a shared, authenticated job identity/authority bridge between ADAM `JobStore`, Dobius `CloudJobStore`, worker enrollment and the eventual `CloudWorkerQueuePort`; specify which store owns idempotency, lease, reservation, process identity and settlement before adding an executor.
2. Extend Dobius’s context handshake use to preserve and bind `projectId` plus `digest` to the run and its events, or define a distinct non-mutating context-pack API. Today ADAM’s handshake returns a minimized identity and Dobius throws it away.
3. Align the ADAM CLI adapter with the current bound terminal-send contract (expected runtime identity and required agent status), and make its bundle guard configurable/platform-aware for the intended workstation/VPS environments.
4. Specify explicit, least-privilege read contracts if ADAM needs monitor or catalog metadata. No such consumption is present; monitor state must remain distinct from capacity reservation, and catalog metadata grants must not become note-content grants.
5. Keep domain documentation synchronized with RPC/UI registrations, then verify the exact packaged build and authenticated endpoints before describing any working-tree integration as deployed.
6. Keep Laya unavailable until a reviewed provider, authenticated authority snapshot, deployment gate, and explicit UI/RPC entrypoint are wired; do not let an advisory output acquire queue or filesystem authority.

These are gaps and follow-up interface questions, not proposed implementation changes in this audit. AWS and external-drive work remain outside scope.
