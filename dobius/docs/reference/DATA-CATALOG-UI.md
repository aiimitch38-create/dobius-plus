# Registered data catalog UI

Knowledge and the phone Files screen list names and bounded metadata from explicitly enrolled roots. Listing does not read original file contents. The desktop host selector is explicit; remote runtime connections can browse metadata but cannot preview registered-root text. The phone route uses its explicit `hostId`.

Preview is a separate, default-off permission for each root. Settings keeps the existing browse-device grant independent from `desktopPreviewEnabled` and the paired-phone preview device IDs. Desktop preview and grant changes use the trusted local UI. Phone preview requires the current paired phone to have both browse and preview access. Unix CLI and remote runtime-scope desktop clients have no preview path.

The user must choose Preview on a listed entry. The client sends the entry ID already returned in that connection's metadata page, validates each response against `data-catalog-preview-schema.ts`, fetches chunks in offset order, and checks the root, generation, version and byte count. After the complete byte sequence arrives, the client validates fatal UTF-8 and text eligibility before asking the server to finish. It discards that validation result and retains no decoded display string while finish is pending. Text is decoded and exposed only after finish, lease, and request-currentness checks succeed. The maximum preview is 256 KiB with 16 KiB chunks. NUL and C0 control bytes other than tab, line feed and carriage return are refused before finish; this is a narrow text-eligibility check, not general file-type detection. HTML, Markdown, links, images, and embedded content render as inert text inside the current view. Preview text is not persisted, sent to an agent, or included in logs.

The desktop client clears preview when the document becomes hidden or the window blurs. The phone client clears it when the route loses focus or AppState is anything other than `active`; unknown AppState values are inactive. Disconnect, root or generation change, explicit close, denial, invalidation, and lease expiry also clear the view. Returning to the foreground never restores text; another explicit Preview action is required. A monotonic lease starts at each `finish` or `renew` request, is capped at 30 seconds, and renews every 10 seconds while the view remains foregrounded. A delayed response cannot extend or revive an expired lease. Already delivered bytes cannot be recalled from a client.

The desktop subscribes to invalidations through the trusted local preload callback; the phone receives them through its current authenticated host client's encrypted event channel. Both clients validate the strict event schema again and clear only when the event root and generation match the active preview. Subscriptions are disposed on desktop blur/hidden state, phone background or route loss, host/target replacement, disconnect, and unmount. Disposed callbacks are ignored, including late events queued by an old host. The 30-second request-start lease and renewal check remain a bound if an invalidation is missed. This UI implementation and its synthetic tests establish source behavior only; they do not establish production enrollment, a live registered-root scan, or physical-phone acceptance.
