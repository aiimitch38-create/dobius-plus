## 2026-08-29 — TASK-ADAM-1.1: shell tool classification and gate (feat/adam-voice-control)
- New `dobius/src/main/jarvis/shell-tool.ts` — pure classification, no execution. `classifyShellCommand(argv, options)` returns `read-only` | `writing` | `denied`.
- Execution model is `execFile` + argv (the `runCli` shape at `agent-context.ts:78`), never a shell. So `>`, `|`, `;`, `&&`, `$(…)` arrive as literal arguments and the whole class of redirection parsing was DELETED rather than defended against. Two tests prove the inertness by side effect: the file `echo hello > /tmp/…` would create does not exist after a real `execFile`, and `; touch` / `&& touch` chain nothing.
- 19-binary read-only allowlist. `osascript` deliberately NOT read-only — "get only" is not decidable from an argv and `osascript -e 'do shell script … with administrator privileges'` is a root escalation, so it is unconditionally `writing`.
- Beyond spec: a binary containing `/` never inherits an allowlist entry by basename, or `/tmp/evil/ls` would pass as `ls`. Denied binaries are still denied by path (`/usr/bin/sudo`).
- Argument scan forces `writing` on allowlisted binaries: find `-delete/-exec/-execdir/-ok/-okdir/-fprint*/-fls`, any `xargs`, any output-file flag. find's `-o` stays read-only — there it is the documented OR operator.
- REVIEW found and fixed a real invariant-B hole: plugin-directory containment was purely lexical, so a symlink pointing at the plugin folder (`cp x.mjs /tmp/notes/x.mjs`) read as harmless in the approval window and still dropped unsigned main-process code into the folder. Now realpaths the token's PARENT (the token is usually a file that does not exist yet) plus `pluginDir`, reusing `resolveEditablePath`'s injectable-`realpath` shape from `self-edit.ts:88`. Test uses a real `symlinkSync` and was verified to FAIL against the old logic before it passed against the fix.
- Carried forward to TASK-ADAM-1.3: argv elements must be coerced with `String(...)` at the IPC boundary — the classifier deliberately does not guard non-string tokens.
- Verified: 62 shell-tool tests; scoped gate 283 passing (221 baseline + 62), exactly one failing file (`attach-main-window-services.test.ts`, pre-existing). Both tsgo configs exit 0. oxlint clean.

## 2026-08-29 — TASK-ADAM-1.2: shell execution and window approval (feat/adam-voice-control)
- New `dobius/src/main/jarvis/shell-command-store.ts` — kept separate from `shell-tool.ts` so classification stays pure and both stay under the 300-line `max-lines` cap. Read-only runs immediately (`execFile`, 30s, 4KB cap, copying `runCli`'s error handling); writing is queued as a `PendingShellCommand`; denied is never queued.
- **Invariant A is enforced structurally, three ways, not just by omitting a tool.** (1) The agent is never told the pending id — `describeForAgent()` returns prose with no id, and the id travels only on the payload to the review window, so a client tool would have nothing to pass. This is the exact opposite of `SelfEditStore`, which hands the agent the id and is why `apply_code_change` is possible there. (2) `runApproved` deletes the entry BEFORE running, so an id cannot be replayed. (3) `jarvis:runApprovedShell` compares `event.sender.id` against the review window's `webContents.id` and refuses anything else — the agent's client tools run in the main window, a different webContents.
- Review window: `self-edit-window.ts` gained `SHELL_COMMAND_PROPOSAL_CHANNEL` + `showShellCommandProposal`, sharing one window and retitling per payload. New `ShellCommandReview.tsx` renders the argv one token per line — a long path after `rm -rf` is easy to skim past on a wrapped line.
- IPC split by WHO IT SERVES rather than by channel: 1.2 owns the human's half (`runApprovedShell`, `discardShellCommand`, `onShellCommandProposal` + preload), 1.3 owns the agent's half (`proposeShell`, client tool, ElevenLabs registration) and runs the WIRING CHECK over both.

(2) The plugin directory was hand-joined in `jarvis-ipc.ts` while 4.1 needs the same folder in two more places — collapsed to one `adamPluginDir()` definition, the drift failure `agent-context.ts:12-18` warns about. (3) The review window reported "Nothing was run" after a command had already run, because the post-run discard is a no-op.

## 2026-08-29 — TASK-ADAM-2.1: model-writable memory (feat/adam-voice-control)
- New `dobius/src/main/jarvis/adam-memory.ts` — six fixed categories (`identity, preferences, projects, relationships, wishes, notes`), plain JSON at `userData/adam-memory.json` so Carson can read or delete it by hand. Free-form categories were QUESTIONED AND CUT: a model handed an open category invents `misc` and memory becomes a junk drawer that eviction cannot reason about. Keys are trimmed/lowercased so `Wife` and `wife ` cannot become two contradictory facts.
- `remember` / `forget` client tools, both `expects_response: true`. Mark LI's `silent: true` was deliberately NOT copied — a `remember` that fails on a bad category or a cap has to be able to say so, and a memory that fails silently is one you stop trusting. `forget` ships WITH the feature rather than later: the motivating incident is Adam confidently reporting the disk 98% full when it was 91%, and a wrong fact you can only overwrite (needing to know the key AND a correct replacement) is worse than no memory.
- Context injection: the budget is SPLIT, not appended. `buildAgentContext` already truncated at 8,000 while the agent prompt is ~8,400, so appending memory after the slice would leave the payload unbounded, and putting memory first inside one slice would let a full memory silently evict the terminal context. `composeAgentContext` reserves memory's actual length and truncates only the machine state.
- REVIEW found TWO real defects, both reproduced with a probe before being fixed, both now covered by a test proven to fail against the pre-fix code.
- **Defect 1 — the key was uncapped.** `entryCost` counts key + value but only the value was capped, so ONE entry could exceed the 2,200 total cap alone, and `evict()`'s `length > 1` guard meant nothing could ever clear it. Measured on the pre-fix code: total cost 10,001 vs cap 2,200, agent payload 10,048 vs budget 8,000, machine state absent entirely — exactly the regression AUTONOMOUS-BUILD.md names, and model-reachable since the model picks the key. Fixed in three places: `MAX_KEY_CHARS = 80`; the `length > 1` guard removed (termination now comes from the protected-entry check, sound only because of the key cap); and `composeAgentContext` caps memory at half the budget as a boundary guard for a hand-edited JSON file.
- **A test's premise was false, which is worse than no test.** The existing boundary test asserted only `not.toContain('Terminal 1')` under the comment "Memory is capped at 2,200 upstream, so this cannot happen in practice". The probe disproved it. Rewritten to assert the length bound AND that the machine state survives, with the measured numbers replacing the wrong comment.
- **Defect 2 — a new fact could evict itself while reporting success.** `evict()` ran over all entries including the one just written; near the cap, an incoming entry whose category ranks first for eviction was the only candidate its own pass would pick. Reproduced: store at 2,178/2,200, `remember` returned `{ok:true}`, the IPC answered "Saved. I'll remember that.", `stored? = false`. Fixed with `evict(protectedKey)`, which skips the entry just written and stops rather than dropping it.
- Falsifiability verified per fix, not in aggregate: reverting the key cap alone fails `keeps one entry inside the total cap even at both maximums`; reverting the protected-key check alone fails `never evicts the fact it was just asked to remember`; reverting the share cap alone fails both `composeAgentContext` bound tests.
- Tool registration extended to a sequential loop over `[PROPOSE_SHELL_TOOL, REMEMBER_TOOL, FORGET_TOOL]`. Sequential, not `Promise.all`: each `ensureClientTool` reads and PATCHes the agent's `tool_ids`, so concurrent calls race and the loser's tool is dropped from a list it never saw.
- WIRING CHECK (`pnpm run build:electron-vite`, exit 0): `jarvis:remember` and `jarvis:forget` in both `out/main` and `out/preload`; all EIGHT renderer tool names present (`ask_adam, get_context, run_dobius, propose_code_change, apply_code_change, remember, forget, propose_shell`), confirming nothing was dropped.
- Invariant A re-verified: the invariant-A test iterates the whole `clientTools` map and its probe payload now carries `category`/`key`/`value` too; neither new tool reaches `runApprovedShell`.
- Verified: scoped gate 343 passing (318 + 25), exactly one failing file (`attach-main-window-services.test.ts`, pre-existing). Both tsgo configs exit 0. oxlint clean on all ten touched files.
