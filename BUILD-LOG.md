- New `dobius/src/main/jarvis/shell-tool.ts` — pure classification, no execution. `classifyShellCommand(argv, options)` returns `read-only` | `writing` | `denied`.
- Execution model is `execFile` + argv (the `runCli` shape at `agent-context.ts:78`), never a shell. So `>`, `|`, `;`, `&&`, `$(…)` arrive as literal arguments and the whole class of redirection parsing was DELETED rather than defended against. Two tests prove the inertness by side effect: the file `echo hello > /tmp/…` would create does not exist after a real `execFile`, and `; touch` / `&& touch` chain nothing.

- Argument scan forces `writing` on allowlisted binaries: find `-delete/-exec/-execdir/-ok/-okdir/-fprint*/-fls`, any `xargs`, any output-file flag. find's `-o` stays read-only — there it is the documented OR operator.

- **REVIEW found the worst defect of this build: the tool map was accidentally a THENABLE, and it hung forever.** The `get` trap returned a dispatch function for any unknown string key, and `then` is an unknown string key. Promise machinery sees a callable `.then`, calls it with (resolve, reject), and waits for a resolve that never comes — the call went to `jarvis:runPlugin` looking for a plugin named `then`. Measured: `typeof tools.then = function`, `await Promise.resolve(tools) => HUNG — never resolved`. The map is handed to the SDK inside the `startSession` options object, so one `await` anywhere upstream would freeze the conversation at startup with no error and nothing in any log — presenting as "the orb just spins". Fixed with a `NEVER_DISPATCHED` set; inherited keys need no listing because `in` walks the prototype chain, and symbols were already excluded, so `then` is the one name that is neither inherited nor a tool.
- **The existing tests could not have caught it**: `Object.entries` does not see proxy fallbacks, so the invariant-A loop walked straight past. That is why invariant A was re-proven under the catch-all with a NEW test that drives the fallback directly using the names an attacker-shaped plugin would pick (`approve_shell`, `run_approved_shell`, `apply_shell`, `plugin_evil`) and asserts all four land on plugin dispatch and none reaches `runApprovedShell`.
- **REVIEW second defect: a type predicate that asserted something untrue.** `isDispatchableName` was `property is string`, but it returns false for plenty of strings (`then`, every real tool), so TypeScript narrowed the false branch to `symbol`. It surfaced as TS2352 and the tempting fix was to force the cast — which would have buried an unsound assertion. Changed to a plain boolean plus `Reflect.get`, the idiomatic proxy accessor, needing no cast and no suppression.
